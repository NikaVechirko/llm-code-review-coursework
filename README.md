# Применение LLM для автоматического поиска и исправления ошибок в коде на C++

Курсовой проект по направлению подготовки **09.03.03 «Прикладная информатика»** (профиль «Искусственный интеллект и аналитика данных»). 

**Учебное заведение:** Кубанский государственный университет (КубГУ), Центр искусственного интеллекта.

**Автор:** Вечирко Ника Вадимовна.

**Год:** 2026.

---

## 📌 О проекте

Данный репозиторий содержит материалы и артефакты исследовательской работы, посвященной сравнительному анализу эффективности современных больших языковых моделей (LLM) в задаче автоматического поиска и исправления ошибок в коде на C++.

**Цель работы:** выяснить, насколько хорошо современные нейросети (как зарубежные, так и отечественные) справляются с ролью «Senior C++ Developer», способны ли они находить скрытые дефекты (утечки памяти, логические ошибки, UB) и предлагать качественные исправления.

**Тестируемые модели:**
*   **DeepSeek** (модель с открытыми весами, известная своей силой в программировании).
*   **YandexGPT 5.1 Pro** (российская модель, адаптированная под русский язык).
*   **Qwen** (мощная модель от Alibaba, популярная в среде разработчиков).

## 🛠 Методика эксперимента

Для обеспечения чистоты эксперимента все модели работали в одинаковых условиях.

1. **Датасет.** Был сформирован набор из 10 изолированных программ на C++, содержащих по одной намеренно внедренной ошибке. Ошибки покрывают 5 категорий:
   *   Синтаксические (пропущенные `;`, непарные скобки).
   *   Семантические (несовместимые типы, вызов несуществующих методов).
   *   Логические (неверные условия, ошибки в алгоритмах).
   *   Времени выполнения (деление на ноль, выход за границы массива).
   *   Управления ресурсами (утечки памяти, `double free`).

2. **Промпт.** Был разработан единый промпт на основе техники **Chain-of-Thought**. Он обязывал модель проводить анализ строго по 5 шагам:
   *   Шаг 1: Синтаксис.
   *   Шаг 2: Типы данных.
   *   Шаг 3: Логика.
   *   Шаг 4: Работа с памятью.
   *   Шаг 5: Деление на ноль.

3. **Оценка.** Ответы моделей проверялись по двум критериям:
   *   *Обнаружение:* Нашла ли модель ошибку.
   *   *Корректность:* Компилируется ли предложенный код, решает ли он задачу и не вносит ли избыточных изменений.

## 📈 Основные результаты

Полный анализ приведен в главе 2.4 курсовой работы. Краткая сводка:

*   **Обнаружение:** Все три модели показали **100% обнаружение** заложенных ошибок (10 из 10) благодаря структурированному промпту.
*   **Качество исправлений (9 из 10):** Ни одна из моделей не справилась идеально со всеми кейсами без избыточности.
*   **DeepSeek:** Показала наилучшее следование инструкциям (точечные правки, деловой стиль). Однако был зафиксирован 1 случай **«галлюцинации»** (в Кейсе 4 модель «придумала» несуществующую синтаксическую ошибку).
*   **Qwen:** Показала самый глубокий уровень знаний C++ (предложила современные альтернативы с `const` и range-based for), но её решения часто носили **избыточный характер** (over-engineering), нарушая инструкцию промпта о минимальных изменениях.
*   **YandexGPT:** Показала стабильный результат, но иногда добавляла в исправленный код лишние элементы, которых не было в исходнике (Кейс 10).

## 🚀 Как воспроизвести

1.  Откройте файл `data/test_cases.md` и выберите любой кейс.
2.  Скопируйте текст промпта из `prompts/chain_of_thought.md`.
3.  Подставьте код кейса в конец промпта.
4.  Отправьте запрос в любую LLM (через веб-интерфейс или API).
5.  Сравните результат с эталонным исправлением из датасета.
