# Кейс №8. Ошибка времени выполнения (выход за границы массива)

## Ответ модели Yandex GPT

**Шаг 1 (Синтаксис):** Ошибок нет — код компилируется без замечаний.

**Шаг 2 (Типы):** Ошибок нет — `arr` — массив `int`, индекс `i` — `int`, типы согласованы.

**Шаг 3 (Логика):** Есть ошибки.

Условие цикла `i <= 3` перебирает индексы 0, 1, 2, 3, то есть 4 итерации вместо 3. Массив содержит только 3 элемента, а вывод требует именно их. Комментария-намерения здесь нет, но задача явно говорит: «вывести все элементы массива» — а их три.

**Шаг 4 (Память):** Есть ошибки.

Прямое следствие шага 3: на последней итерации `i == 3` происходит обращение к `arr[3]` — выход за границы массива (в C++ массив из 3 элементов имеет допустимые индексы 0–2). Это неопределённое поведение: может напечататься мусор, а с флагами санитайзера программа аварийно завершится.

**Шаг 5 (Деление):** Ошибок нет — операций деления в коде нет.

**Вывод:** Единственный дефект — ошибка «на единицу» (off-by-one) в условии цикла `i <= 3`. Из-за неё цикл выполняет 4 итерации и читает память за пределами массива. Правильное условие — строгое неравенство `i < 3`, ещё надёжнее — `i < sizeof(arr) / sizeof(arr[0])`, чтобы условие пересчитывалось автоматически при изменении размера массива.

**Исправленный код:**

```cpp
#include <iostream>
using namespace std;

int main() {
    int arr[3] = {1, 2, 3};
    for (int i = 0; i < 3; ++i) {
        cout << arr[i] << " ";
    }
    return 0;
}
```

Вывод программы: `1 2 3 `.

## Ответ модели Qwen

**Шаг 1 (Синтаксис):** Ошибок нет.

**Шаг 2 (Типы):** Ошибок нет.

**Шаг 3 (Логика):** Есть ошибки — условие `i <= 3` даёт 4 итерации (`i = 0, 1, 2, 3`) вместо 3; по условию задачи нужно вывести только элементы массива `{1, 2, 3}`.

**Шаг 4 (Память):** Есть ошибки — на последней итерации происходит чтение `arr[3]`, выход за границы массива (допустимые индексы 0..2). Это неопределённое поведение: в консоль попадёт мусорное значение, возможны повреждение стека и падение программы. Утечек и двойного удаления нет (динамическая память не используется).

**Шаг 5 (Деление):** Ошибок нет.

**Вывод:** Классическая ошибка «off-by-one» в условии цикла: `i <= 3` вместо `i < 3`. Приводит к выходу за границы массива `arr[3]` (UB) и выводу лишнего мусорного элемента. Остальных дефектов нет.

**Исправленный код:**

```cpp
#include <iostream>

int main() {
    const int arr[] = {1, 2, 3};
    const int size = static_cast<int>(sizeof(arr) / sizeof(arr[0]));
    for (int i = 0; i < size; ++i) {
        std::cout << arr[i] << " ";
    }
    std::cout << '\n';
    return 0;
}
```

Вариант в современном стиле (C++11 и выше) — исключает ошибку границ в принципе:

```cpp
#include <iostream>

int main() {
    const int arr[] = {1, 2, 3};
    for (int value : arr) {
        std::cout << value << " ";
    }
    std::cout << '\n';
    return 0;
}
```

**Пара замечаний от ревьюера сверх шаблона:**

- `using namespace std;` в глобальной области — плохая практика, лучше явные `std::`.
- Массив сделан `const`, так как он не изменяется; размер вычисляется из самого массива, чтобы при добавлении элементов цикл не пришлось править руками.
